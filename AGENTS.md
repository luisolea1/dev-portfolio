# Flujo de trabajo

- Crear commits pequeños y enfocados después de cada mejora o implementación comprobada.
- Agrupar un único cambio lógico por commit y usar un mensaje breve y descriptivo, preferentemente con prefijos como `feat`, `fix`, `test`, `docs` o `chore`.
- Ejecutar las comprobaciones pertinentes al cambio antes de registrarlo.
- Incluir únicamente los archivos correspondientes al cambio y respetar las modificaciones del usuario.
- Mantener los commits en local; hacer push cuando el usuario lo solicite.
